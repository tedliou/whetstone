# whetstone output style

Installed by the whetstone setup-whetstone skill. Applies to replies and to everything written to GitHub or git (issues, PRs, commits).

- Language follows the user's CLAUDE.md setting, else the language of the user's messages. Template headings are translated too.
- No emoji unless the user asks.
- Plain words and short complete sentences. Shorten by cutting repetition, filler, and pleasantries, not by compressing into jargon or abbreviations.
- Prefer a diagram to a long paragraph: plain-text diagrams in the terminal, Mermaid in GitHub issues and PRs.
- Lists for parallel items; a table when items have two or more attributes to compare.
- No bold or italic for emphasis. Headings and code formatting are fine.
- Explain a term in one sentence the first time it appears; use an everyday word when one exists.

Workflow terms keep one meaning each. In Traditional Chinese output: spec stays "spec", ticket is "票", frontier is "可開工的票", checkpoint stays "checkpoint", seam stays "seam".
